# R27U91 / MacMix DDC 故障定位

测试日期：2026-10-07。显示器：R27U91，EDID vendor 20588、product 9988；Apple Silicon Mac。

## 已完成的独立写入对照

正式版和诊断版 MacMix 均已退出，独立工具通过相同 Apple Silicon IOAVService 通道执行。每次设置使用 MacMix 的两次相同数据包发送时序，前后仅查询 0x62 与 0x8D。下面三个实验均由用户实际确认声音状态。

| 实验 | 唯一设置命令 | 发送缓冲区 | 读回 current | 用户确认 |
|---|---|---|---|---|
| A | 0x62 = 40 | `84 03 62 00 28 F2` | 0x62=40、0x8D=1 | 有声音，物理菜单可调 |
| B | 0x8D = 2 | `84 03 8D 00 02 37` | 0x62=40、0x8D=0 | 声音消失 |
| C | 0x8D = 1 | `84 03 8D 00 01 34` | 0x62=40、0x8D=1 | 声音恢复 |

所有设置 I/O 均返回 `00000000`。B/C 没有设置音量；音量始终为 40，无需重置显示器即可使声音消失或恢复。

这是对 `0x8D` 写入值兼容性的直接因果验证：这台显示器写入 2 导致无声，写入 1 恢复声音。MacMix 公开源码使用 `isMuted ? 1 : 2`，与本显示器的实测行为不一致。[ddcutil 文档](https://www.ddcutil.com/vcpinfo_output/)列出的常见 MCCS 定义为 1 静音、2 解除静音，因此不能将这台显示器的实测映射推广到所有显示器。

## 诊断版实际运行日志

来源：GitHub `ljmng7/MacMix` 提交 `7412749`，只增加日志、使用独立应用标识并停止自动更新。

启动读取成功：current=50、maximum=65535；并未采用默认 maximum=100。

拖动结束时：slider=0.4019592401573348、maximumUsed=65535、value=26342（`66 E6`）。底层实际发送 `84 03 62 66 E6 5A`，I/O 成功。显示器读回 `00 E6`（230），物理菜单显示 100%，声音仍正常。

该会话记录 87 次 WRITE_BEGIN，命令全部为 0x62；没有 REQUEST_MUTE，也没有 0x8D 写入。

这解释了诊断版该次没有触发实验 B 中的无声问题，并实证了另一个问题：按显示器报告的 maximum=65535 换算，无法让滑块百分比与本显示器实际音量范围对应。读回值等于写入值低字节，提示可能发生截断；不能仅凭一次样本确定显示器内部实现。

## 修复方向与尚未确认事项

1. 针对此显示器提供静音命令兼容设置，或允许禁用 0x8D，以音量 0 和恢复原音量实现静音/解除静音。不要全局反转所有显示器的 1/2 定义。
2. 针对此显示器允许配置音量有效最大值为 100；例如 40% 写整数 40，而不是按 65535 放大。
3. 尚未捕获用户已安装正式版那次拖动所发送的数据包；因此不能声称已经证明正式版的那次故障一定发送了 0x8D=2。公开源码在拖动且内部认为已静音时存在请求解除静音的路径，应继续核对该分支。

原始日志保留在测试机器上；此文档记录经过整理的测试结果，未上传原始会话日志。

测试结束状态：0x62 current=40、0x8D current=1，用户确认声音已恢复。

## 作者修改与测试入口

本分支 `ddc-diagnostics` 基于上游提交 `7412749`，包含已编译测试的诊断日志代码。欢迎向本 fork 的 `ddc-diagnostics` 分支提交 Pull Request，测试者可合并后编译验证。

- Apple Silicon 底层记录实际发送的数据包、读取响应和 I/O 状态；Intel 底层未增加这些日志。
- 诊断版名称为 `MacMix DDC Diagnostic`，应用标识独立，自动更新关闭；诊断代码没有改变原有 DDC 值换算或静音映射。
- 测试时完全退出正式版，避免两个应用同时发送 DDC。
- 日志位置：`~/Library/Logs/MacMix-DDC-Diagnostic/`。
- 使用完整 Xcode 构建：`bash script/build_ddc_diagnostic.sh`。若 Xcode 不在默认位置，先设置 `DEVELOPER_DIR` 指向其 `Contents/Developer`。
- 本次验证：Apple Silicon Debug 构建成功，产物通过 `codesign --verify --deep --strict`；日志写入及十六进制输出已验证。显示器声音结果为测试者实际确认，I/O 成功不等同于显示器正确执行。
